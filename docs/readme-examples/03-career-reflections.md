# 第三版：職涯困難、成果與解題方式

## 我遭遇了哪些讓我感到困難的問題？

具體技術上有 vibe coding；思維方式上，則是平行、有計畫、有目標地做事。

### Vibe coding

頭兩個月，在 AI agent 剛開始時，有 GPT Codex 5.1 模型。我嘗試透過 vibe coding 創造具有 UI 介面的數據視覺化工具、改動已有軟體結構且以 IDS SDK 開發的 UI 程式，以及重構技術債較多的韌體通訊 UI 程式。

我在韌體通訊 UI 程式卡住。首先，我的程式碼只有通訊和 UI 介面的原始碼，沒有韌體的程式碼；其次，我下給 AI 的 prompt 不夠具體，也不夠工程化。最後找到解決方向，是透過理解 LLM AI 的本質——AI 的極限是你的極限，AI 是放大器。

1. **Vibe coding 還不是 AI 能做到的。** AI 目前需要人去評價。生成的能力讓它能完成各種事，但好壞目前仍需要人評斷，vibe anything still unwork。
2. **把 AI 需要的完整資訊提供給它。** Context engineering 對 AI 非常重要，它能知道的就是你給它的那些資訊。

得到解答的過程花了兩個月，大部分時間都花在 vibe，但 vibe 本身並沒有給我帶來有用的「認知或資訊」。它只讓我發現程式開發在什麼情況下會發生問題：沒有架構或基礎可以「模仿」，以及存在太多模糊性。

讓我得到解答的是與人交流。不論是逛 Reddit，得知 vibe coding 本身不可行，只有 AI with software engineering；或是和其他外包人員聊技術，知道他的 AI prompt 像過去軟體工程的規格那樣具體、有定義。除了 vibe coding 事情本身的知識，我覺得自己解決問題的方法也進步了。

### 平行、有計畫、有目標地做事

我是以直覺、探索和深度發想來思考和做事。工作後，很大比例的情況是同時處理多件事情，或是事情要做到什麼目標已經很明確。這是我比較不習慣的做事方法：我會在一件事情中發現其他問題，或認為有更重要的事，而過於深入或離題。

並非我的習慣只有缺點，或是大家都要以同樣的節奏做事。但一方面，我與公司的做事方法有差距；另一方面，我太依賴個人思考，有點過頭了。所以，我在兩個月內適應現在公司的節奏和做事方法。

## 我如何解決問題

### 影像演算法分析和設計

1. **問題：**如何解決影像演算法判定的問題？
2. **設計：**加入 6 個區間判定、以 sin 波回歸作為目標函數，以及以 6 個中心點的直線線性回歸作為目標函數。
3. **證據：**很多實驗、真實影格、同一支影片前後的曲線，以及多支影片的比較。
4. **成果：**依專案定義，修改了主要的 3 種演算法：振幅的背光法、振幅的正光法，以及偏擺的背光法。

這是我運用專業知識較多的部分，具體設計如下。

#### 加入 6 個區間判定

邊緣判定有兩個要求：

1. 週期性的凹槽會影響邊緣判定，因此加入一段區間，減少這種週期誤差。
2. 邊緣有雜訊，因此需要多個區段，把不行的區段捨棄。

要用一段區間作機率平均，同時也要有多個區段，才能進行取捨。

#### 加入 sin 波回歸作為目標函數

我的量測設備沒有一個很好的基準，因此以這種結構化的特性直接作為好壞的基準。但要注意，在量值上仍不確定其正確性。

#### 以 6 個中心點的直線線性回歸作為目標函數

同樣利用結構化的特性，直接作為好壞的基準。
