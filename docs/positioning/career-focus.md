# 以職涯經驗作為個人首頁主軸

## 為什麼調整介紹方向

後續求職介紹以職涯經驗為優先。工作紀錄中已有產品開發、實驗驗證與現場問題處理的經驗，首頁應先呈現這些內容，讓訪客理解目前的工程能力。學校作品保留在後面，補充技術背景。

本文依據本機的 `AI_engineering-main/AI_engineering-main/profile/work_experience_log&decision.md` 整理。原始紀錄保留在被 Git 忽略的資料夾，這裡保存個人介紹的整理方向。

## 工作紀錄能呈現的四個重點

| 首頁可呈現的方向 | 紀錄中的具體內容 |
| :--- | :--- |
| 影像量測系統開發 | 軟體與演算法開發、相機／光源／硬體實驗、量測驗證。 |
| 設備控制軟體開發 | 超音波驅動軟體、設備通訊、參數設定與操作流程。 |
| 工程流程與產品文件 | SOP、實驗格式、測試報告、操作文件與版本發布。 |
| AI 協作實踐 | 使用 AI 協助開發、數據分析與文件製作，根據實際結果修訂方法。 |

## 一句話定位

> 影像量測與工程軟體開發｜實驗驗證與 AI 協作

## 自我介紹草稿

> 我有電機工程背景，工作經驗涵蓋影像量測系統與設備控制軟體，包括演算法開發、相機與光源實驗、軟體驗證及產品文件。
>
> 我關注如何從實際使用情境定義問題，透過實驗與數據檢查方法，並把經驗整理成可重用的工作流程。目前也持續探索 AI 在軟體開發、數據分析與技術文件中的應用。

## 首頁作品排序

1. 影像量測開發。
2. 設備控制軟體。
3. AI 工程實踐。
4. 學校研究與作品，作為補充。

工程流程與產品文件可結合前三項案例介紹，說明如何保存實驗、驗證結果與操作知識。

## 如何使用工作日誌

把紀錄整理成「負責的問題、採取的做法、可展示的產出」，並區分已完成的工作、嘗試中的方法與事後反思。選用能公開、能說明個人貢獻的內容；沒有依據的成效數字保留待確認。

AI Engineering 可以連結到這些實際工作經驗，呈現使用 AI 時遇到的問題、調整過的方法與後續整理方向。
