# GitHub 個人檔案：介紹與版面設計

## 個人檔案的用途

GitHub 個人檔案可以理解成你的工程師名片與作品入口。它應該讓訪客很快回答：你是誰、擅長什麼、做過什麼、哪個作品值得點進去。

這份文件整理個人頁應呈現的資訊與閱讀順序，作為後續撰寫介紹與安排版面的依據。

## 介紹應包含哪些區塊

| 區塊             | 應該放什麼                                  | 作用                 |
| :--------------- | :------------------------------------------ | :------------------- |
| 姓名與一句話定位 | 名字、主要領域、關注的問題。                | 第一眼認識你。       |
| 簡短自我介紹     | 背景、經驗、做事方式，約 2–4 行。          | 理解你的特色。       |
| 精選作品         | 2–4 個作品，各有一句介紹、個人貢獻與連結。 | 看到實際能力。       |
| 技術與目前方向   | 有作品支持的技能、正在投入的主題。          | 知道你的專長與發展。 |
| 交流方式         | 聯絡或討論入口。                            | 知道怎麼找到你。     |

## 首頁閱讀順序示例

以下保留以學校作品為主的初版草圖，示範資訊安排。後續求職介紹以職涯經驗為優先，請搭配[職涯定位說明](../positioning/career-focus.md)與[第二版 README](../readme-examples/02-career.md)閱讀。

## 資訊層次與視覺原則

設計重點是資訊層次，讓訪客先認識你，再找到感興趣的作品，最後知道如何深入了解或交流。

- **上方簡潔、定位清楚：** 姓名、一句話定位與簡短介紹，讓人快速掌握背景與方向。
- **中間讓作品成為主角：** 精選少量代表作，每個作品提供摘要、個人貢獻與清楚的連結。
- **下方補充技能與交流入口：** 技能對應實際作品，聯絡方式容易找到。
- **視覺保持一致：** 橫幅、配色與圖示用來建立風格，配合標題與留白呈現閱讀層次。
- **裝飾適量：** 技術徽章少量使用，避免搶走作品的注意力。

## 個人首頁如何介紹作品

每個作品的摘要回答三件事：

1. **作品是什麼？** 用一句話說明主題或處理的問題。
2. **呈現哪項能力？** 說明自己的貢獻，以及讀者能從作品看見的能力。
3. **去哪裡看？** 提供對應專案的閱讀入口。

例如，`AI_engineering-main` 是個人首頁中的一個作品。首頁保留摘要與入口；完整方法、流程、模板與進度由專案本身負責說明。
